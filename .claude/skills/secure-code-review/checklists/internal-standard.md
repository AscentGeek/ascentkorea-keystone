## 0. 점검 시 사용 방법
- 코드에서 아래 항목을 위반한 사실이 보이면 지적사항에 **위반 기준 ID**(예: `WEB-01`)를 적는다.
- 권고 단계이므로 위반은 "표준 위반(권고)"으로 기록하고, 배포를 막는 근거로 쓰지 않는다. 심각도는 1절 규칙에 따른 실제 영향 기준이다.
- 이 표준에 없는 취약점도 OWASP/CWE 기준으로 지적한다. 이 표준은 점검 범위를 줄이지 않는다.
- 항목에 위반이 없으면 보고서에 적지 않는다(양호 사항에만 근거를 기록).

## 1. 판정 규칙

### 1.1 분류 (확정 / 조건부)
- **확정**: 위반이 코드·설정에서 확인되고, 공격자가 **다른 취약점이나 repo 밖의 특수 조건 없이** 악용할 수 있다.
- **조건부**: 위반은 확인되지만 악용에 아래 중 하나가 필요하다. 조건을 지적사항에 **반드시 명시**한다.
  - 다른 취약점의 선행 (예: XSS가 있어야 토큰 탈취 가능)
  - repo 밖 설정 (예: 앞단 프록시가 헤더를 덮어쓰지 않는 경우)
  - 특정 기능의 활성화 (예: 플래그를 켠 환경)
- **하드닝 항목**(`WEB-*`, `CI-*`, `DEP-01`): 위반 사실이 확인되면 **확정**으로 기록한다. 심각도는 항목 기본값을 쓴다.
- 이 규칙으로도 갈리면 보수적으로 **조건부**로 하고 이유를 적는다.

### 1.2 심각도
- 기본값은 아래 항목 표의 "기본 심각도"다. 실제 영향과 도달성으로 **최대 1단계** 조정할 수 있고, 조정 사유를 적는다.
- **조건부이면서 도달 경로를 코드에서 찾지 못한 경우**: 기본 심각도에서 1단계 낮추되, "조건이 충족되면 ○○으로 재평가"를 영향 항목에 적는다.
- 아래 경우는 기본값보다 올린다: 인증 없이 도달 가능, 운영 시크릿 노출, 전체 사용자에게 영향(단일 프로세스 중단 포함).

### 1.3 의존성 취약점(CVE)의 심각도 매핑
스캐너(trivy 등)의 등급을 그대로 쓰지 않고 **도달성**으로 정한다.

| 스캐너 등급 | 취약 기능이 앱 경로에서 확인됨 | 도달 여부 미확인 (조건부) | 도달 불가 (제외) |
|---|---|---|---|
| Critical | Critical (확정) | High (조건부) | 제외 |
| High | High (확정) | Medium (조건부) | 제외 |
| Medium | Medium | Low | 제외 |
| Low | Low | Info | 제외 |

- **도달 불가** 예: 빌드 전용 의존성, 호출하지 않는 함수, 다른 OS 한정 취약점, 사용하지 않는 옵션. 제외 목록에 **CVE ID와 사유**를 적는다.
- 취약점이 많은 패키지는 **패키지 단위로 한 건**으로 묶어 기록한다. CVE ID와 fixed 버전은 스캐너 출력(`trivy.json`)에서 인용하고, 가장 높은 fixed 버전을 조치 방안으로 제시한다. 기억으로 쓰지 않는다.
- 의존성 점검 도구가 FAILED/SKIPPED이면 CVE 결과는 **확정할 수 없다**고 종합 의견에 명시한다.

### 1.4 오탐 판정 기준
오탐으로 제외하려면 **코드 인용 근거**가 있어야 한다. 아래는 오탐 근거로 인정하지 않는다.
- "이스케이프했다"는 이유만으로 정규식 탐지를 제외 (`INP-03` 참고. 이스케이프해도 반복 와일드카드 조합으로 폭발할 수 있다)
- 입력의 출처를 확인하지 않고 "사용자 입력이 아닐 것"이라 판단
- 테스트 코드라는 이유만으로 시크릿 탐지 제외 (값이 실제 키 형식이 아닌 경우만 제외)
- 점검 도구가 해당 파일을 파싱하지 못한 경우를 "문제 없음"으로 처리 (미점검으로 기록)

### 1.5 조치 권고 기한 (초안 값, 확정 필요)
| 심각도 | 권고 기한 |
|---|---|
| Critical | 7일 |
| High | 30일 |
| Medium | 다음 릴리스 (90일 이내) |
| Low / Info | 백로그 |

권고 단계에서는 보고서의 "목표일"을 정하는 **참고값**으로만 쓴다.

## 8. 보안 담당자가 확정해야 할 항목
1. 1.2절 심각도 조정 폭(±1단계)과 1.3절 의존성 매핑표가 회사 위험 수용 수준에 맞는지
2. 1.5절 조치 권고 기한 값
3. 각 항목의 기본 심각도 (특히 CI-01, BIZ-02, WEB-01)
4. 문서 소유자, 승인자, 개정 주기
5. **권고에서 필수로 전환할 항목과 시점.** 제안: 2개 분기 동안 점검 결과의 오탐률과 수정률을 본 뒤, 영향이 큰 `SEC-01`, `INP-01`, `ACC-01`, `AUTH-01`부터 필수로 전환
6. 개인정보 취급 기준(수집·저장·마스킹). 외부 법규 요구가 정해지면 `DATA-*` 항목으로 추가
